# 🌸 サクラメーター — 飲食店クチコミ健全性チェック(β)

Googleマップの公開情報から、飲食店のクチコミが「サクラ(やらせクチコミ)的なパターン」と
どれだけ一致するかを**参考値**として表示する、個人開発の無料Webアプリです。

**公開URL**: <https://wakuwaku-labs.github.io/sakura-meter/>(GitHub Pages・無料ホスティング)

> **大切な前提**: 本アプリの表示は統計的な推定による参考値であり、
> 特定店舗によるサクラ利用の事実を断定・証明するものではありません。
> 詳しくはアプリ内の「免責・法的配慮」をご覧ください。

---

## 1. すぐに試す(デモモード・完全無料)

APIキーなしで、架空の店舗データを使って全機能を体験できます。

```bash
cd "/Users/katagirijakutou/飲食店　サクラチェッカー" && python3 -m http.server 8000
```

ブラウザで <http://localhost:8000> を開いてください。
デモの店舗・クチコミ・投稿者名はすべて架空で、実在の店舗とは関係ありません。

## 2. 実際の店舗を検索する(誰でも設定不要)

公開版(<https://wakuwaku-labs.github.io/sakura-meter/>)は、**訪問者が何も設定しなくても**
全国の実在の飲食店を検索・分析できます。運営者が用意した無料の代理サーバー(Cloudflare Workers)
経由でGoogleマップに接続する仕組みになっており、費用は運営者が負担します。

### アーキテクチャ(なぜ0円を保証できるか)

```
訪問者のブラウザ ──▶ GitHub Pages(画面・静的ファイル)
                          │ fetch()
                          ▼
                Cloudflare Worker(代理サーバー・無料)
                          │ 月間カウンタをKVでチェック
                          │ 上限内のみ中継
                          ▼
                Google Places API(運営者のキーはWorker内の
                シークレットとしてのみ保持。ブラウザには一切渡らない)
```

- 運営者のGoogle Maps APIキーは **Cloudflare Workerの環境変数(シークレット)としてのみ存在**し、
  ブラウザ・HTMLソース・GitHubリポジトリのどこにも含まれません。
- 各リクエストの前にWorkerが**月間の利用回数をKV(Cloudflareのキーバリューストア)でチェック**し、
  上限(検索・分析・新着順取得それぞれ月900件。各SKUの無料枠に対し余裕を持たせた値)に達したら
  Google APIへは中継せず、その場でエラーを返します。**割り当て超過のリクエストは課金対象になりません**
  (Googleへの通信自体が発生しないため)。
- Cloudflare Workers・KVともに無料枠内で運用しており、クレジットカード登録も不要です
  (無料枠: リクエスト10万件/日、KV読み取り10万件/日・書き込み1,000件/日)。

上限に達した月は、自動的にデモデータでの表示に切り替わり、翌月また利用できます。

### 自分専用のAPIキーを使いたい場合(任意)

共有枠を消費したくない方、地図プレビュー機能を使いたい方は、右上「設定」から
ご自身のGoogle Maps Platform APIキーを登録できます。この場合、共有の代理サーバーは使わず、
従来どおりブラウザから直接Googleへ問い合わせます。

1. [Google Cloud Console](https://console.cloud.google.com/) で Google アカウントにログインし、新しいプロジェクトを作成
2. 「お支払い」で請求先アカウント(支払い方法)を登録(無料枠の範囲内でもこの設定は必須です)
3. 「APIとサービス → ライブラリ」から次の2つを**有効化**
   - **Maps JavaScript API**
   - **Places API (New)**
4. 「APIとサービス → 認証情報」で **APIキー** を作成
5. キーに制限をかける(推奨)
   - アプリケーションの制限: 「ウェブサイト」→ `https://wakuwaku-labs.github.io/sakura-meter/*`
   - APIの制限: 上記2つのAPIのみ許可
6. 公開版を開き、右上の「設定」からAPIキーを貼り付けて保存

APIキーはお使いのブラウザ(localStorage)にのみ保存され、外部へは送信されません。

### 無料枠についての補足(自分のキーを使う場合)

- 2025年3月の料金体系変更により、Google Maps Platform の無料枠はSKU単位の月間無料呼び出し件数制です(Enterprise系SKUは月1,000件)。新着順の取得に使う Places API (Legacy) は別SKU扱いで、既存の枠を消費しません。
  詳細: <https://mapsplatform.google.com/pricing/>
- 想定外の課金を避けるため、Cloud Console の「割り当て」画面で1日あたりの上限を低めに設定し、
  ¥0の予算アラートを併用することをおすすめします。

## 5. スコアの算出方法(概要)

サクラ投稿の見分けは、実務・学術のいずれでも次の4軸(A〜D)で整理されます。ただし**評価分布(D)は判定に必要なデータが公式APIから取得できない**ため採点していません(理由は「限界について」)。実際に採点しているのは、残る3軸に評価水準と低評価クチコミの質を加えた8つのシグナルです。

| 軸 | シグナル | 重み | 内容 |
|---|---|---|---|
| A. 文体・表現 | 本文の定型度 | 31% | 短文・定型フレーズ・具体性の欠如・過度な絶賛・文面の使い回し。率直な留保があれば減点 |
| A | 文体の均質性 | 8% | 別人の投稿なのに語彙・文末・文字数が揃いすぎていないか(AI生成・業者量産の痕跡) |
| A | ★5と本文の乖離 | 10% | ★5評価のうち本文が15文字未満(空を含む)のものの割合 |
| B. 投稿タイミング | 高評価の投稿時期の集中 | 16% | **高評価(★4以上)**のうち「最も密集する3件」が何日間に収まるか。新着順が取れた店舗では直近の投稿状況も直接確認 |
| C. 投稿者アカウント | 投稿者名の傾向 | 8% | 姓名フルネーム型の表示名の比率、同一表示名の重複 |
| D. 評価水準 | 評価水準の偏り | 9% | 件数補正後の平均評価の上振れ |
| D | 周辺相場との乖離 | 7% | 周辺店舗の評価分布からの突出度 |
| E. 低評価クチコミの質 | 低評価の酷評度 | 11% | ★1〜2が具体的な不満の説明ではなく罵倒・全否定だけになっていないか。低評価どうしの類似・短期集中も |

### クチコミの取得方法(重要)

Google公式APIは1回の取得につきクチコミを**最大5件**しか返さず、しかも新APIでは**関連度順**のみで投稿日時順を指定できません。これが本アプリの精度を最も強く縛る制約でした。

そこで2通りの取得を組み合わせています。

| 取得 | API | 並び | 件数 |
|---|---|---|---|
| 関連度順 | Places API (New) Place Details | most relevant | 最大5件 |
| 新着順 | Places API (Legacy) Place Details `reviews_sort=newest` | newest | 最大5件 |

投稿者名＋投稿日時で重複を除いてマージし、各クチコミに取得元(`relevant` / `newest` / `both`)を付けます。新着順が取れることで、以下が**初めて測定可能**になりました。

- 真の直近投稿の集中(関連度順の偏りを受けない)
- 「短期集中の後、ぱたりと投稿が止まる」パターン(発注が終わった形)
- 新しい低評価の取得(攻撃レビューは新しいため、関連度順から漏れやすい)

Legacy 側は `reviews_no_translations=true` を付け、機械翻訳ではなく原文を受け取ります。取得に失敗した場合(Legacy未有効・上限超過)は関連度順のみで動作を続けます。

### パターンの「向き」(重要)

やらせクチコミには**正反対の2方向**があります。

- **高評価の水増し**(A〜D軸) — 店舗側が★5を積み増す。疑われるのは**店舗**
- **低評価の攻撃**(E軸) — 競合など第三者が来店せずに酷評★1を書く。疑われるのは**投稿者側**で、お店は**被害者**

メインスコアは主に前者を測るため、低評価工作を受けている店では**数値が低く出ます**。数値だけを見て「問題なし」と読み違えられないよう、不自然さの向きを必ず添えて表示し、低評価側が一定以上のときは**独立した数値**としても表示します。

低評価側の判別で見ているのは「酷評であること」ではなく**「酷評 × 具体性の欠如」**です。本物の不満客は何を注文し何が起きたかを具体的に書く傾向があり、来店していない投稿はそれを書けないため罵倒だけになりやすい——この性質を使っています。具体性を伴う低評価は正当な苦情として大きく減点します。

補正の仕組み:

- データ不足のシグナルは除外して重みを再配分
- **複数一致係数**: 高い値を示したシグナルが1つ以下なら×0.85、3つ以上なら×1.10(「1つの兆候だけで決めつけない」原則の実装)
- **緩和要因**: 本文を伴う★2〜4の率直な評価があればスコアを緩和。★1は「お椀型(二極化)」というサクラ側のパターンにも該当するため緩和材料に数えない。高評価だけが短期集中している場合は緩和幅を半減
- **具体性ゲート**: 具体的記述が多いクチコミでは「文体の均質性」の減点を最大80%まで弱める(丁寧に書く常連が多い店の誤検知対策)
- **酷評の緩和材料からの除外**: 酷評型と判定した★2は緩和に数えない(低評価工作を受けている店ほどスコアが下がる逆転を防ぐ)
- **翻訳文の除外**: Googleが機械翻訳して返した外国語クチコミは「文体の均質性」から除外(翻訳エンジンの文体に揃い、業者量産と誤判定されるため)
- 信頼度(低・中・高)は「分析に使えたデータ量」を表す指標

### チェックリスト(14項目)

スコアとは別に、同じ軸を人が目視で使える14項目に翻訳して表示します。実務で使われる「3項目以上に該当したら疑いが高い」という目安に合わせ、該当数をそのまま開示します。判定に必要なデータがない項目は「判定不可」として、該当・非該当のどちらにも数えません。

### 数値の根拠にしている実証研究

- Luca & Zervas (2016) "Fake It Till You Make It: Reputation, Competition, and Yelp Review Fraud", *Management Science* 62(12) — 偽の疑いでフィルタされたレビューは★1・★5に極端化する
- 坂口洋英(2022)「レビューの不正操作に関するサーベイ」(経済産業省) — 日本のAmazonで削除レビューの★5比率は74%(非削除は55%)

この55%と74%は本来「★5比率が高すぎないか」の基準に使えますが、星ごとの件数を取得する手段が公式にないため**採点には使えていません**。Luca & Zervas の「★1・★5への極端化」という知見は、低評価側を別軸(E)で評価する設計と、★1を緩和材料に数えない判断の根拠として使っています。

### 限界について

- **日本語で書かれたクチコミしか本文を分析できません。** 文章解析(定型フレーズ・具体性マーカー・体験動詞・酷評語)はすべて日本語の語彙依存です。外国語に当てるとどのパターンにもマッチせず「具体性がない」と誤判定するため、日本語以外は解析対象から外します。日本語の高評価クチコミが2件に満たない場合は**スコアを算出せず「分析不可」**とします(中核である本文分析なしに、評価の高さや投稿時期だけで判定すると人気店を誤って疑うため)。
- クチコミは1回の取得につき**最大5件**という制限があります。関連度順(Places API New)と新着順(Places API Legacy の `reviews_sort=newest`)の2通りを取得してマージすることで**最大10件**まで増やしていますが、数百件あっても分析できるのはごく一部です。
- 新着順の取得は **Places API (Legacy)** に依存しています。2025年3月に凍結され新規プロジェクトでは有効化できないため、将来提供が終了する可能性があります。取得できなかった場合は関連度順のみで分析し、その旨を結果画面と信頼度に反映します。
- 実務上は**投稿者アカウントの調査(レビュー総数・プロフィール・他店への評価履歴)が最も有効**とされますが、公式APIは投稿者の表示名しか返しません。この軸に8%しか置けていないのは本ツールの構造的な弱点です。
- **星ごとの件数(評価の分布)を取得する手段がありません。** 公式APIは分布を提供せず、Googleマップの画面からの取得は Google Maps Platform 利用規約 3.2.3(a)「No Scraping」および Google マップ追加利用規約 2(c) が禁じています(第三者のスクレイピング系APIも実体は同じ)。平均評価と件数だけから分布を復元するのは数学的に不可能で(自由度が足りず、仮定を置けばその仮定を出力するだけ)、推定は「測っているふり」にしかなりません。そのため**「お椀型」の判定は行っていません**。代わりに、表示できたクチコミの平均が店舗全体の平均からずれている場合は注意書きとして表示します。
- 生成AIによるクチコミは日本語として自然なため、従来の「不自然な日本語」という手掛かりは効きません。
- テレビ・SNSでの話題化などサクラ以外の理由でも似たパターンは生じます。
- 低評価側(E軸)の判定も、最大5件の中に★1〜2が2件以上含まれていなければ行えません。実際には低評価が多くても、関連度順の抽出から漏れて判定できないことがあります。
- 本当にひどい体験をした利用者も、詳細を書かずに強い言葉で短く済ませることがあります。酷評そのものは正当な意見であり、本ツールの数値は投稿者を非難するものではありません。

結果は「クチコミを自分の目で確かめるきっかけ」としてご利用ください。

## 6. 法的・倫理的な設計方針

- 表示は「サクラ的パターン一致度(参考値)」とし、断定表現を使わない
- すべてのシグナルに根拠と「サクラ以外の可能性(代替説明)」を併記
- 店舗のランキング化・ブラックリスト化機能を持たない
- データは公式APIから取得し、保存・蓄積しない(Google Maps Platform 規約準拠)
- デモデータはすべて架空(実在店舗を例示に使わない)
- 2023年10月施行の景品表示法ステマ規制についての解説をアプリ内に掲載
